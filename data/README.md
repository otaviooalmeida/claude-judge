# Benchmark data

`tasks/tasks.jsonl` contains the drafted 48-task set. Candidate A is generated by Haiku and candidate B by Sonnet; both are judged by both judge models.

- 8 calibration tasks: two per category
- 40 evaluation tasks: ten per category

This is an AI-assisted, human-reviewed synthetic dataset. Before any paid generation run, review every passage, instruction, and `referenceChecklist` and record corrections in version control.

## Verbosity controls

After reviewing natural candidates, run `npm run verbosity:template`. For each of the 20 preselected tasks, verify that `shortCandidate.text` is concise and edit `longCandidate.text` to add wording or organization without adding substantive information. Run `npm run verbosity:finalize`; this writes the reviewed short/long candidates to `data/candidates/verbosity.jsonl`. The main judge command loads that file automatically.

## Human annotation

After candidate responses have been generated, create a blank annotation file with `npm run annotate:template`. Copy `data/human/evaluations.template.jsonl` to `data/human/evaluations.jsonl`, then fill it in before viewing any Claude judgments. For every candidate pair, record:

```json
{"taskId":"factual-01","candidateAId":"factual-01-a","candidateBId":"factual-01-b","candidateA":{"correctness":2,"relevance":2,"completeness":2,"unsupportedClaims":false},"candidateB":{"correctness":1,"relevance":2,"completeness":1,"unsupportedClaims":true},"preference":"a"}
```

Use the 0/1/2 anchors and preference priority documented in `docs/design.md`. Do not label from the automated judgment output. Keep calibration labels separate from the held-out evaluation labels.

## Candidate and results files

- `candidates/candidates.jsonl`: frozen generated candidates.
- `results/judgments-haiku.jsonl`: Haiku judge results.
- `results/judgments-sonnet.jsonl`: Sonnet judge results.
- Calibration results use the `-calibration.jsonl` suffix.
- `results/plan.json`: exact paid request plan and cost estimate.

These files are intentionally not generated by the offline scaffold until the dataset has been reviewed and a paid stage is explicitly authorized.
